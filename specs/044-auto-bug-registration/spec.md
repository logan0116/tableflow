# Feature Specification: 测试验收不通过时批量登记缺陷

**Feature Branch**: `044-auto-bug-registration`
**Created**: 2026-11-24
**Status**: Draft

## 背景与问题证据

`tf-test-check` 判定测试验收不通过时，只把未通过项列在错误信息里就退出，看板上一条缺陷都不会出现。缺陷目前全靠人工登记——2026-11-24 那轮 20 条缺陷全是脚本补录的。

验收不通过恰恰是最该留下缺陷记录的时刻：不登记，看板的「Bug 管理」永远是干净的，发布条件里的「Bug 是否清空」也就失去意义。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 判定不通过时自动留下缺陷 (Priority: P1)

测试验收被拒后，缺陷表里能看到这次为什么没过，不必再手工补录。

**Why this priority**: 缺陷是测试域的产物；验收不通过却不留缺陷，等于把判断依据丢在日志里。

**Independent Test**: 对一个有失败执行记录的版本跑测试验收，缺陷表新增一条记录并挂到该版本。

**Acceptance Scenarios**:

1. **Given** 本版存在执行结果未通过的用例，**When** 测试验收判定不通过，**Then** 缺陷表新增一条缺陷并挂到该版本的 `Bug管理`
2. **Given** 本版存在回归未通过的依赖需求，**When** 判定不通过，**Then** 缺陷证据里列出这些变更单编号
3. **Given** 判定不通过且缺陷已登记，**When** 查看该版本，**Then** `Bug管理` 包含这条新缺陷

### User Story 2 - 汇总与去重，不刷屏 (Priority: P1)

十条用例失败只留一条汇总缺陷，重复跑不重复建，已有未关闭的同类缺陷只追加证据。

**Why this priority**: 逐条建缺陷会让缺陷表被同一原因淹没；重跑一次又新建一批，缺陷数就失去意义。

**Independent Test**: 连续跑两次测试验收，缺陷总数不变；第二次只更新证据清单。

**Acceptance Scenarios**:

1. **Given** 本版有 3 条用例执行失败，**When** 登记缺陷，**Then** 只新建 1 条缺陷，证据里列出 3 个用例号
2. **Given** 同版本同类别已有未关闭缺陷，**When** 再次判定不通过，**Then** 不新建，只把新的用例号并入证据
3. **Given** 同版本同类别已有缺陷但已 `closed`，**When** 再次判定不通过，**Then** 新建一条新缺陷，不复用历史已关闭记录

### Edge Cases

- 项目没有缺陷表时，跳过登记并在报告里说明，不影响验收判定本身
- 失败用例的来源规格缺失时，缺陷的关联规格留空，不阻断登记
- 未关闭缺陷本身就是缺陷，不再为它们重复建缺陷

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 判定不通过时 MUST 登记缺陷；判定通过时 MUST NOT 新建缺陷
- **FR-002**: 缺陷 MUST 按「版本 + 类别」汇总，同一类别多条未通过项合并为一条缺陷
- **FR-003**: 缺陷证据 MUST 列出全部未通过项的编号（用例号或变更单号）
- **FR-004**: 已有未关闭（open/fixing/verifying）的同版本同类别缺陷时 MUST 追加证据，不得新建
- **FR-005**: 已有缺陷已 `closed` 时 MUST 新建，不复用历史记录
- **FR-006**: 缺陷字段 MUST 填：标题、状态 `open`、严重度、来源、发现版本号、证据
- **FR-007**: 登记缺陷 MUST NOT 改变验收判定结果——判定仍按原闸门给出 `failed`

### Key Entities

- **缺陷行**：`编号`、`标题`、`状态`、`严重度`、`来源`、`关联规格`、`发现版本号`、`证据`、`剩余事项`
- **类别**：执行结果未通过、变更回归未通过（未关闭缺陷不重复登记）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- 验收不通过后，缺陷表出现对应记录，且挂在该版本上
- 连续两次判定不通过，缺陷总数不增加，只更新证据
- 验收通过时缺陷数不变

## Non-Goals

- 不自动把缺陷置 `closed`（关闭仍由修复与验证驱动）
- 不为未关闭缺陷重复登记
- 不改变 `tf-test-check` 的四项闸门判据
