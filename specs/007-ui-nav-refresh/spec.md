# Feature Specification: 左侧项目导航与全局刷新（v0.5.0）

**Feature Branch**: `007-ui-nav-refresh`

**Created**: 2026-11-19

**Status**: Draft

**Input**: User description: "1. 项目列在左边吧，作为导航的形式 2. 界面提供一个刷新按钮"

## Clarifications

### Session 2026-11-19

- Q: 左侧导航放什么？ → A: 只放项目（项目 → 表格仍是页内标签页），不改导航层级、不做表格树。
- Q: 刷新刷什么？ → A: 重新拉取项目列表、当前项目的表格列表、当前表格的字段与数据；保留当前项目、当前表格与筛选关键字。
- Q: 刷新时旧数据怎么处理？ → A: 保留旧内容直到新数据返回，不整页闪骨架；失败走既有错误态。
- Q: 刷新失败后怎么重试？ → A: 错误态的「重试」与页头「刷新」共用同一条刷新链路。
- Q: 刷新时当前项目/表格已不存在？ → A: 回退到列表第一项（项目 → 该项目的第一张表）。
- Q: 要做窄屏/移动端适配吗？ → A: 不做，宪法非目标清单明确排除移动端适配；侧栏固定宽度，窄窗口下内容区自行横向滚动。
- Q: 刷新按钮放哪？ → A: 页头右侧，与行数统计同组，任何内容状态下都可见（含加载、空、错误态）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 项目列表作为左侧导航 (Priority: P1)

项目从页面上方的横向按钮改为左侧竖排导航，内容区占据右侧。切换项目后，右侧表头面包屑、表格标签页与数据随之切换；当前项目在导航中有明确选中态，项目多时侧栏内滚动。

**Why this priority**: 项目是看板的第一层入口，横向按钮在项目增多后换行、挤占表格高度；竖排导航把入口固定在一侧，也给表格让出整块宽度。

**Independent Test**: 打开页面，左侧看到全部项目且当前项目高亮；点击另一个项目，右侧面包屑与表格切换；项目多到超出视口时侧栏自身滚动、表格区宽度不变。

**Acceptance Scenarios**:

1. **Given** 项目列表已加载，**When** 渲染页面，**Then** 项目位于内容区左侧的竖排导航内，右侧为页头与表格内容。
2. **Given** 当前项目为A，**When** 查看导航，**Then** A有可见选中态（背景与文字色区分）且带 `aria-current="page"`。
3. **Given** 项目数量超过侧栏可视高度，**When** 页面渲染，**Then** 侧栏内部滚动，页头与表格区不被推出视口。
4. **Given** 点击导航中的项目B，**When** 切换完成，**Then** 页头面包屑显示B、表格标签页为B的表格、数据为B首张表的数据。
5. **Given** 项目列表为空或加载失败，**When** 渲染，**Then** 侧栏仍存在并给出状态占位，不消失、不撑破布局。

---

### User Story 2 - 全局刷新按钮 (Priority: P1)

页头右侧提供「刷新」按钮。点击后重新拉取项目、表格与当前表数据；刷新期间按钮显示进行中并禁点，当前项目、当前表格与筛选关键字保持不变。

**Why this priority**: 看板的价值是「看到的就是当前状态」（宪法原则II无读缓存）。Agent写入后，人需要一个不必刷新浏览器、不丢当前上下文的入口。

**Independent Test**: 停在某项目的第3张表并输入筛选词，点刷新：数据更新、表格仍是第3张、筛选词仍在；按钮在请求期间禁点并显示「刷新中」。

**Acceptance Scenarios**:

1. **Given** 任意内容状态（加载 / 空 / 错误 / 正常），**When** 查看页头，**Then** 刷新按钮可见且可点（刷新进行中除外）。
2. **Given** 当前为项目A的表格T2且筛选为「完成」，**When** 点击刷新，**Then** 请求项目列表、A的表格、T2的数据各一次；完成后仍停在T2，筛选仍为「完成」。
3. **Given** 刷新请求进行中，**When** 查看按钮，**Then** 按钮为禁用态、`aria-busy="true"`、文案为「刷新中」。
4. **Given** 刷新失败，**When** 请求结束，**Then** 内容区显示既有错误态（含重试），按钮恢复可点。
5. **Given** 刷新时发现当前项目已被删除，**When** 结果返回，**Then** 自动切到列表第一个项目及其首张表，不报错、不白屏。

---

### Edge Cases

- 项目列表为空：侧栏显示「暂无项目」，刷新仍可点；新建项目后点刷新即可出现。
- 当前项目没有表格：侧栏选中态保留，内容区显示「暂无表格」，刷新不报错。
- 当前表格没有可见字段：沿用「暂无字段」空态。
- 刷新与切换项目/表格并发：后发起的导航结果优先，不被先发起的刷新结果覆盖。
- 刷新期间再次点击按钮：按钮已禁用，不产生重复请求。
- 筛选关键字在刷新后不再匹配：显示「0 / N条」，不自动清空关键字。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 项目列表MUST以左侧竖排导航呈现，位于内容区左侧；右侧内容区宽度自适应剩余空间。
- **FR-002**: 导航项MUST显示项目 `name`；当前项目MUST有可见选中态并带 `aria-current="page"`。
- **FR-003**: 侧栏MUST固定宽度并独立滚动；项目数增多MUST NOT挤压表格可用宽度或把表格推出视口。
- **FR-004**: 页头MUST提供刷新按钮，触发重新拉取项目列表、当前项目表格列表、当前表格数据；MUST NOT新增接口、MUST NOT引入缓存。
- **FR-005**: 刷新MUST保留当前项目、当前表格与筛选关键字；当前项目或表格已不存在时MUST回退到列表首项，MUST NOT报错或白屏。
- **FR-006**: 刷新请求进行中，按钮MUST禁用并显示进行中状态；结束后MUST恢复。
- **FR-007**: 刷新失败MUST走既有错误态（EmptyState + 重试）；错误态的「重试」与页头「刷新」MUST共用同一条刷新链路。
- **FR-008**: 刷新过程中MUST NOT清空已展示内容再闪回骨架（首次加载与切换项目/表格除外）。
- **FR-009**: 前端MUST NOT硬编码业务列名、项目名或状态值（宪法原则III）；只使用接口返回的 `name`。
- **FR-010**: 界面文案MUST全部中文；MUST NOT引入新依赖、MUST NOT改动后端接口与数据模型。
- **FR-011**: MUST NOT做移动端/窄屏适配（宪法非目标）；仅保证桌面窗口下的布局与滚动。
- **FR-012**: 首屏 ≤500ms、滚动 ≥50fps的性能基线MUST不回退。

### Key Entities

- **项目导航（ProjectNav）**：左侧竖排项目列表，输入项目数组与当前项目id，输出选择事件；只使用 `id` 与 `name`。
- **刷新动作（RefreshAction）**：按 项目列表 → 当前项目表格 → 当前表格数据 的顺序重新拉取，失败时进入错误态。
- **页头动作区（HeaderActions）**：承载行数统计与刷新按钮。

## Success Criteria *(mandatory)*

- **SC-001**: 1280×800窗口下，项目导航在左、内容在右，页面无横向溢出；项目数超出侧栏高度时侧栏独立滚动，表格区宽度不变。
- **SC-002**: 点击刷新，网络面板可见 `GET /api/projects`、`GET /api/projects/{id}/tables`、`GET /api/tables/{id}/table` 各一次；刷新后当前表格与筛选词不变。
- **SC-003**: 刷新进行中按钮 `aria-busy="true"` 且 `disabled`；结束后两属性恢复。
- **SC-004**: 前端 `npx tsc --noEmit` 零错误、`npm run build` 成功；后端 `pytest -q` 全绿（不回归）。
- **SC-005**: 前端源码grep不到 `TITLE_NAMES` 式业务列名；`scripts/contrast_check.py` 仍5/5达标。

## Assumptions

- 只改前端渲染与交互，后端接口、数据模型、审计逻辑均不变。
- 项目与表格的数量级沿用001基线（20项目 / 每项目10表 / 单表500行）。
- 现有 `reloadKey` 刷新链路可替换为显式刷新函数；不保留两套并行加载逻辑。
