# Feature Specification: 版本表瘦身与三比率（v0.6.4）

**Feature Branch**: `016-board-slim`

**Created**: 2026-11-19

**Status**: Draft

**Input**: 需求 016-AR。`tableflow` 项目自身的版本表仍是旧结构（17字段，含开发进度/测试进度/未清Bug数/Bug已清空/回归通过/文档状态/场景总数/任务总数），展示冗杂且判定口径与 `board@2` 契约不一致；需要一个界面能直接看懂的三比率视图。

## 背景与问题证据

| 问题 | 证据 | 影响 |
|---|---|---|
| 旧指标与契约冲突 | 线上 `tf-ver` 仍有 8 个旧字段，`board@2` 契约里没有 | 看板与契约两套口径，新人看不懂哪套算数 |
| 判定散落在四个字段 | 旧 `发布条件` = 开发进度∧回归通过∧Bug已清空∧文档状态 | 每加一个维度就要改一次公式 |
| 无法一眼看出进度 | 只有百分比与布尔，没有"已完成/总数" | 必须点开关联弹层才数得清 |
| 关联字段名不一致 | 旧名"需求关联（独立）/（依赖）" | 与"独立需求/依赖需求"的叫法对不上 |

## Clarifications

### Session 2026-11-19

- Q: 3/5 怎么显示？ → A: 扩展引擎新增 `ratio` 计算类型，输出 `"3/5"` 文本；前端只渲染文本，不画进度条（列太宽）。
- Q: 发布条件怎么算？ → A: 三个布尔之与：独立需求是否完成、依赖需求是否完成、上一版本Bug是否清空。
- Q: 存量怎么办？ → A: 只迁 `tableflow` 项目；迁移前已导出 JSON 与 sqlite 备份。
- Q: 其余项目？ → A: 不在本需求内，后续用 skill 逐个更新。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 三比率一眼看懂 (Priority: P1)

打开版本表，能看到三列比率：独立需求已完成/总数、依赖需求已完成/总数、上一版本Bug已修复/总数，只显示文本。

**Independent Test**: `v0.6.0` 行显示 `4/4`、`0/0`、`1/1`，进度条分别为满、空、满。

**Acceptance Scenarios**:

1. **Given** 版本挂了 4 份规格且全部 accepted，**When** 查看该行，**Then** 独立需求比率为 `4/4`。
2. **Given** 版本未挂依赖需求，**When** 查看该行，**Then** 比率为 `0/0`，不报错也不显示为空。
3. **Given** 关联行被删除（悬空引用），**When** 重算，**Then** 悬空项不计入分母。

### User Story 2 - 三个布尔决定发布条件 (Priority: P1)

`发布条件` 只由三个布尔合成：独立需求是否完成、依赖需求是否完成、上一版本Bug是否清空。

**Acceptance Scenarios**:

1. **Given** 三表都达标，**Then** `发布条件=是`。
2. **Given** 任一项未达标，**Then** `发布条件=否`。
3. **Given** 某版本没有依赖需求，**Then** 该项为空集，判为"是"（无此类工作）。

### User Story 3 - 旧指标彻底消失 (Priority: P2)

版本表不再出现开发进度、测试进度、未清Bug数、Bug已清空、回归通过、文档状态、场景总数、任务总数。

**Acceptance Scenarios**:

1. **Given** 版本表字段清单，**When** 核对，**Then** 上述 8 个字段 id 均不存在。
2. **Given** 两个关联字段，**When** 查看表头，**Then** 名称为"独立需求管理"与"依赖需求管理"。

## Requirements *(mandatory)*

- **FR-001**: 引擎新增 `ratio` 计算类型，配置为 `{"kind":"ratio","source":<relation>,"where":{...}}`，输出"已完成/总数"文本，空集为 `"0/0"`。
- **FR-002**: `ratio` 不计入悬空引用（与 `count` 同口径）；源行变化后同事务重算并落库。
- **FR-003**: `ratio` 不可标记 `gate`（非布尔字段）。
- **FR-004**: 前端识别 `kind=ratio`，只渲染 `n/m` 文本（等宽数字），不画进度条；`0/0` 照常显示。
- **FR-005**: 版本表新增三个比率字段与三个布尔字段，`发布条件=and(三布尔)`。
- **FR-006**: 两个关联字段改名为"独立需求管理""依赖需求管理"；`发布条件`排在`发布状态`之前。
- **FR-007**: 删除 8 个旧字段；删除前先改 `发布条件` 的依赖，避免悬空。
- **FR-008**: 仅迁移 `tableflow` 项目，其余 6 个项目不改。

## Success Criteria *(mandatory)*

- **SC-001**: `pytest` 全绿，新增 `ratio` 用例不少于 4 条。
- **SC-002**: `tableflow` 版本表 7 行的三个比率均可算出，且与人工核对一致。
- **SC-003**: 迁移前后行数不变，备份可回滚。

## Non-Goals

- 其余 6 个项目的迁移。
- 契约文件升版（由 017 承担）。
- 任务总数/场景总数的替代指标。
