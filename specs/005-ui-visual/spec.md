# Feature Specification: 界面视觉打磨（v0.4.0）

**Feature Branch**: `005-ui-visual`

**Created**: 2026-11-10

**Status**: Draft

**Input**: User description: "界面我想做一些美化"——在 004 已交付的 enum 标签、数字对齐、sticky 首列、骨架、空状态、密度、列宽记忆之上，解决三处仍然存在的问题：结构层次看不见、列名装不下、页面层级弱。

## 背景与问题证据

004 之后界面已可用，但实测仍有三个问题（2026-11-10 在 1280×800 视口截图与色值计算）：

| 问题 | 证据 | 影响 |
|---|---|---|
| 结构层次看不见 | 斑马纹 `#fafbfc`、表头底 `#f6f8fa`、行分隔线 `#eaeef2`、悬停底 `#eef4fb` 对白底的对比度分别为 1.04/1.06/1.17/1.11:1 | 长表扫读时行、列、悬停位置难以定位 |
| 列名装不下 | 「需求关联（独立）」与「需求关联（依赖）」都渲染为「需求关联…」；5 个 speckit 列分别渲染为 `speckit-c…`/`s…`/`p…`/`t…`/`i…` | 列身份丢失，用户无法判断该看哪一列 |
| 页面层级弱 | h1 固定为「只读状态看板」，不反映当前项目与表；表格卡片直接贴页面底，3 行数据后出现 400px+ 空白 | 不知道自己在哪个项目/表；页面看起来"没做完" |

## Clarifications

### Session 2026-11-10

- Q: 配色方向？ → A: 沿用 GitHub Primer 浅色风格，只加深结构色（表头带、行分隔线、容器边框、悬停底），不换主题、不做深色模式（宪法非目标）。
- Q: 列宽怎么定？ → A: 字段类型基础宽与表头文字估算宽取大值，钳制在 88–320px；纯字符数估算（中文按 1 字宽、西文按 0.55 字宽），不用 canvas、不做 DOM 测量。
- Q: 表头被截断怎么办？ → A: 默认宽度优先保证表头完整；超过 320px 上限时截断并给 `title` 全文。
- Q: 页头显示什么？ → A: 「项目名 › 表名」，右侧显示「共 N 条」；`h1` 语义保留，项目切换器与表标签保留现有位置。
- Q: 表格卡片高度？ → A: 最大高 `calc(100vh - 200px)`，不强制最小高；卡片加圆角与浅阴影形成面板感，行少时空白由页面背景承担。
- Q: 明细弹层布局？ → A: 改为竖向键值对（字段名左、值右）；容器宽度 ≥720px 时两列，否则单列；值保留全文换行。
- Q: 交互反馈范围？ → A: 关联链接改悬停下划线，按钮加 120ms 过渡，行悬停加 80ms 过渡；不引入动画库。
- Q: 字体？ → A: 显式中文栈 `PingFang SC, Hiragino Sans GB, Noto Sans CJK SC, Microsoft YaHei`，不打包字体文件。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 结构层次可见 (Priority: P1)

表头像一条独立的带子，行与行之间有清晰但不抢眼的边界，鼠标悬停的行一眼可辨。用户扫一屏 20 行时不需要用手指着找行。

**Why this priority**: 这是"看起来专业"与"看起来潦草"的主要差别，且纯 CSS 可改，风险最低。

**Independent Test**: 计算表头底、行分隔线、容器边框、悬停底对白底的对比度，逐项对照阈值；截图对比改前改后。

**Acceptance Scenarios**:

1. **Given** 表格渲染完成，**When** 计算表头底与白底对比度，**Then** ≥1.12:1。
2. **Given** 表格渲染完成，**When** 计算行分隔线与白底对比度，**Then** ≥1.25:1。
3. **Given** 表格容器，**When** 计算容器边框与白底对比度，**Then** ≥1.50:1。
4. **Given** 鼠标悬停某行，**When** 计算悬停底与白底对比度，**Then** ≥1.15:1，且首列 sticky 同步变色。
5. **Given** 斑马纹开启，**When** 渲染 20 行，**Then** 偶数行底色与白底对比度 ≥1.04:1（保持 Primer 淡斑马纹，不加重）。

---

### User Story 2 - 列宽自适应 (Priority: P1)

打开一张新表，列宽按字段类型与表头长度自动给出合理初值；表头文字不被无意义截断，`speckit-*` 五列能区分。

**Why this priority**: 列身份丢失直接影响读表，是当前最硬的可用性缺陷。

**Independent Test**: 打开「独立规格需求」表，5 个 speckit 列表头完整显示；打开「版本管理」表，「需求关联（独立）」与「需求关联（依赖）」完整区分。

**Acceptance Scenarios**:

1. **Given** 首次打开某表（无列宽记忆），**When** 渲染列宽，**Then** 每列宽度 ≥ 该列表头估算宽，且 ≤320px。
2. **Given** number 字段，**When** 渲染默认列宽，**Then** 宽度取 100px 与表头估算宽的较大值。
3. **Given** datetime 字段，**When** 渲染默认列宽，**Then** 宽度取 132px 与表头估算宽的较大值。
4. **Given** enum 字段，**When** 渲染默认列宽，**Then** 宽度取 124px 与表头估算宽的较大值。
5. **Given** relation 字段，**When** 渲染默认列宽，**Then** 宽度取 156px 与表头估算宽的较大值。
6. **Given** text 字段，**When** 渲染默认列宽，**Then** 宽度取 168px 与表头估算宽的较大值。
7. **Given** 首列，**When** 渲染默认列宽，**Then** 在通用规则基础上再加 16px。
8. **Given** 表头文字超过 320px 上限，**When** 渲染，**Then** 截断为省略号，且 `title` 提供全文。
9. **Given** 已有列宽记忆，**When** 打开该表，**Then** 记忆宽度优先，不被默认规则覆盖。

---

### User Story 3 - 页面层级与弹层信息架构 (Priority: P2)

页头告诉用户"在哪个项目、哪张表、多少条"，表格是页面上明确的一块面板；点开关联明细时，字段与值竖排，长文本不再被挤成一行。

**Why this priority**: 影响第一眼观感与明细可读性，但涉及组件结构调整，排在 P1 之后。

**Independent Test**: 切换项目/表，页头文字跟随变化；缩放到 1280×800 与 1920×1080，卡片与弹层布局正常；明细弹层中 40 字以上文本换行显示。

**Acceptance Scenarios**:

1. **Given** 选中项目 `tableflow` 与表「版本管理」，**When** 渲染页头，**Then** 显示「tableflow › 版本管理」。
2. **Given** 表格加载完成，**When** 渲染页头右侧，**Then** 显示「共 N 条」；筛选生效时显示「M / N 条」。
3. **Given** 视口高度 800px，**When** 渲染表格卡片，**Then** 卡片最大高不超过 `100vh - 200px`，且不出现双滚动条。
4. **Given** 卡片处于空表状态，**When** 渲染，**Then** 卡片高度贴合内容，不撑出大片白底。
5. **Given** 打开关联明细弹层，**When** 容器宽度 ≥720px，**Then** 键值对两列排布；否则单列。
6. **Given** 明细中某字段值 60 字，**When** 渲染，**Then** 值换行全文显示，不被截断。
7. **Given** 弹层打开，**When** 按 Esc 或点击遮罩，**Then** 关闭弹层。

---

### Edge Cases

- 字段名为空字符串：按 0 宽估算，回退类型基础宽。
- 表头为纯西文长词（如 `speckit-constitution状态`）：按中文 1 字宽 + 西文 0.55 字宽混合估算。
- 列数 ≤3 且总宽小于容器：表格仍铺满容器（现有 `min-width: 100%` 行为不变）。
- 表格有 500 行：列宽估算只在表头变化时计算，不随行数增长。
- 明细弹层字段值为空：显示「—」占位，保持行高。
- 视口高度 <600px：卡片最大高退化为 `70vh`。
- 深色系统偏好（`prefers-color-scheme: dark`）：本版不实现深色主题，保持浅色，不报错。

## Requirements *(mandatory)*

### Functional Requirements

**结构色**

- **FR-001**: 表头底对白底对比度 MUST ≥1.12:1。
- **FR-002**: 行分隔线对白底对比度 MUST ≥1.25:1。
- **FR-003**: 表格容器边框对白底对比度 MUST ≥1.50:1。
- **FR-004**: 行悬停底对白底对比度 MUST ≥1.15:1；sticky 首列 MUST 同步使用同一底色。
- **FR-005**: 结构色 MUST 只通过 `styles.css` 的 CSS 变量调整；MUST NOT 引入新颜色体系或主题切换。

**列宽自适应**

- **FR-006**: 首次打开（无记忆）时，列宽 MUST 取「字段类型基础宽」与「表头估算宽」的较大值。
- **FR-007**: 类型基础宽 MUST 为：number/computed 数字 100px、datetime 132px、enum 124px、relation 156px、text 168px、其它 computed 120px。
- **FR-008**: 表头估算宽 MUST 按字符宽度累加（中文 14px/字、西文 7.5px/字符）加左右内边距 24px 计算；MUST NOT 使用 canvas 或 DOM 测量。
- **FR-009**: 默认列宽 MUST 钳制在 88–320px；首列 MUST 在通用规则上 +16px；用户拖拽范围保持 004 的 48–600px，不受默认值上下限约束。
- **FR-010**: 表头 MUST 在超过列宽时截断为省略号，并通过 `title` 提供全文。
- **FR-011**: 已记忆的列宽 MUST 优先于默认规则，不被覆盖。
- **FR-012**: 列宽估算 MUST NOT 随数据行数增长而重复计算。

**页面层级与弹层**

- **FR-013**: 页头 MUST 显示「项目名 › 表名」；表格就绪后 MUST 在右侧显示「共 N 条」或「M / N 条」。
- **FR-014**: 表格卡片 MUST 有圆角与浅阴影；最大高 MUST 为 `calc(100vh - 200px)`，视口 <600px 时退化为 `70vh`。
- **FR-015**: 关联明细弹层 MUST 改为竖向键值对布局；容器 ≥720px 时两列，否则单列。
- **FR-016**: 明细弹层 MUST 支持 Esc 与点击遮罩关闭。
- **FR-017**: 关联链接 MUST 默认无下划线、悬停显示下划线；按钮与行悬停 MUST 有过渡（按钮 120ms、行 80ms）。

**通用**

- **FR-018**: 界面文案 MUST 全部中文；MUST NOT 新增业务列名硬编码。
- **FR-019**: 本 spec MUST NOT 引入新依赖、MUST NOT 使用 canvas/虚拟滚动/重型表格库。
- **FR-020**: 性能基线 MUST 保持：14 行首屏 ≤500ms、关闭硬件加速滚动 ≥50fps、无 >50ms 长任务。
- **FR-021**: 本 spec MUST NOT 改变接口契约、MUST NOT 改变业务数据与 localStorage 键名。
- **FR-022**: 数字列列头与单元格的右内边距 MUST 一致（12px），数字与表头右边缘不得错位。

### Key Entities

- **列宽估算（ColumnWidthEstimate）**：由字段 `type`、`name`、是否首列推导出的像素宽度，只在字段集合变化时重算。
- **结构色令牌（SurfaceTokens）**：表头底、行分隔线、容器边框、悬停底四个 CSS 变量。
- **页头（PageHeader）**：项目名、表名、行数计数的组合展示。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 四项结构色对比度分别达到 1.12/1.25/1.50/1.15:1 阈值（按 WCAG 相对亮度公式计算）。
- **SC-002**: 「独立规格需求」表中 5 个 speckit 列表头完整显示，不再出现同前缀歧义（`speckit-c…`/`s…`/`p…`/`t…`/`i…`）；1280px 视口下允许横向滚动。
- **SC-003**: 「版本管理」表中「需求关联（独立）」与「需求关联（依赖）」表头完整显示。
- **SC-004**: 首次打开表格的列宽计算耗时 <5ms（500 行表实测），且滚动帧率不下降。
- **SC-005**: 页头随项目/表切换更新；「共 N 条」与筛选后计数一致。
- **SC-006**: 明细弹层中 60 字文本完整换行显示，Esc 与遮罩点击均可关闭。
- **SC-007**: `cd frontend && npx tsc --noEmit` 零错误；`cd backend && .venv/bin/pytest -q` 全绿。
- **SC-008**: 首屏 ≤500ms、滚动 ≥50fps、无 >50ms 长任务；视觉评审（VL 模型 + 人工）确认层次优于改前。

## Assumptions

- 004 已交付列宽记忆、密度、sticky 首列、enum tone；005 只在其上调整默认值与布局。
- 列宽估算采用字符近似而非真实测量，允许 ±10% 误差；用户仍可拖拽微调并记忆。
- 浅色主题为唯一主题；深色模式、主题切换仍在宪法非目标清单内，不在本 spec 范围。
- 不引入前端测试框架；验收以 `npx tsc --noEmit`、计算样式核对、截图与 VL 评审为准。

## 未来范围

- 深色模式、主题切换、移动端适配、列显示/隐藏配置、视图体系（分组/看板/甘特）仍属宪法非目标，不在本 spec 范围。
