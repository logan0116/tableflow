# Feature Specification: 只读状态看板（v0）

**Feature Branch**: `001-readonly-dashboard`

**Created**: 2026-11-06

**Status**: Draft

**Input**: User description: "一个只读看板（v0），替代现在用 smart_table（192.168.1.155:8093）『看一眼状态』的用途。原来的平台不删、继续作为数据源和写入口；本项目读同一份结构化数据。分工等式：人只读、Agent 读写。多项目管理。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 打开即见当前状态 (Priority: P1)

用户打开看板，选择一个项目，直接看到该项目当前的数据行，不需要登录、不需要点刷新、不需要等待同步。页面上的每个值都必须是此刻数据存储里的值。

**Why this priority**: 这是看板存在的全部理由。如果不能"打开即见当前状态"，用户仍然会回到原平台，功能没有替代价值。

**Independent Test**: 在数据存储改掉某一行的一个值，然后新开页面选择该项目，页面上显示的是新值。

**Acceptance Scenarios**:

1. **Given** 数据存储中某项目有14行数据，**When** 用户打开看板并选择该项目，**Then** 页面显示该14行，列顺序与字段定义一致。
2. **Given** 用户上次打开过该项目且某值已变化，**When** 用户重新打开页面，**Then** 页面显示变化后的新值，不出现旧值。
3. **Given** 数据存储不可达，**When** 用户打开页面，**Then** 页面显示明确的错误提示与重试入口，且不显示任何旧数据。
4. **Given** 页面已显示某项目数据，**When** 用户选中某单元格文字并复制，**Then** 复制内容为该单元格的显示文本。

---

### User Story 2 - 在多个项目之间切换 (Priority: P2)

用户管理多个项目，需要在一个页面里切换查看，而不是记住每个项目的地址。

**Why this priority**: 多项目是既定使用场景；没有它，用户要为每个项目单独开一个页面，替代价值大打折扣。

**Independent Test**: 在数据存储中放入两个项目的数据，打开看板，在两个项目之间来回切换，每次切换后看到的是对应项目的数据与列。

**Acceptance Scenarios**:

1. **Given** 数据存储中有多个项目，**When** 用户打开看板，**Then** 页面列出全部项目名称，并默认展示其中一个。
2. **Given** 用户正在查看项目 A，**When** 用户切换到项目 B，**Then** 页面显示项目 B 的数据行与列，且不再显示项目 A 的任何行。
3. **Given** 项目 B 没有任何数据行，**When** 用户切换到项目 B，**Then** 页面显示"暂无数据"的空表状态，而不是错误。

---

### User Story 3 - 增删列只改数据 (Priority: P3)

项目的数据结构会变：新增一列（如"负责人"）、删除一列（如废弃的"备注"）。这类变化必须只改数据，不改应用代码，也不需要重新部署。

**Why this priority**: 列是业务配置。若改一列要发版，看板就会因为"改不起"而逐渐失真。

**Independent Test**: 在数据中新增一条字段定义并补上该列的值，刷新页面后新列出现；删除该字段定义后刷新，该列消失，页面无报错。

**Acceptance Scenarios**:

1. **Given** 某项目已有若干列，**When** 在数据层新增一列字段定义并写入对应值，**Then** 刷新页面后该列按定义的位置与类型显示，期间没有任何代码改动或重新部署。
2. **Given** 某项目有一列字段定义，**When** 删除该字段定义，**Then** 刷新页面后该列消失，其余列正常显示。
3. **Given** 某列被标记为不可见，**When** 用户打开该项目，**Then** 该列不出现在表格中，但其数据不被删除。

---

### Edge Cases

- 项目没有任何数据行：显示"暂无数据"的空表状态，保留列头，不报错。
- 单元格值为空：显示为空单元格，不出现 `null`、`undefined`、`NaN` 等字样。
- 字段类型无法识别（数据中出现了未支持的类型）：按纯文本显示该列内容，页面不报错、不空白。
- 数据存储响应超时或报错：显示错误提示与重试入口，不显示上一次会话的旧数据。
- 项目数量较多（如20个）：项目切换区仍可用，不出现溢出导致的不可点。
- 单项目行数较多（如500行）：表格可通过滚动查看全部行，不截断、不丢行。
- 两个使用者同时打开同一项目：各自独立读取，互不影响。
- 浏览器关闭硬件加速：滚动仍然可用，不出现明显卡顿。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 列出数据存储中的全部项目，并允许用户选择一个项目查看其数据。
- **FR-002**: 系统 MUST 在每次打开或刷新页面时重新读取数据存储；页面 MUST NOT 展示上一次会话或上一次请求留下的数据。
- **FR-003**: 系统 MUST 以表格形式呈现所选项目的数据行；列的顺序与可见性 MUST 由字段定义决定。
- **FR-004**: 列的集合 MUST 由数据中的字段定义决定。新增或删除一列 MUST 只需修改数据，不需要修改应用代码或重新部署。
- **FR-005**: 系统 MUST 按字段类型呈现单元格（至少覆盖文本、数字、日期时间、枚举），未识别的类型 MUST 回退为纯文本显示。
- **FR-006**: 界面文案 MUST 全部为中文。
- **FR-007**: 系统 MUST 为只读：MUST NOT 提供新增、编辑、删除数据行的入口或接口。
- **FR-008**: 数据存储不可达或超时，系统 MUST 显示明确的错误提示与重试入口，且 MUST NOT 用旧数据填充页面。
- **FR-009**: 所选项目没有数据行时，系统 MUST 显示"暂无数据"的空表状态（保留列头），MUST NOT 显示错误。
- **FR-010**: 表格行数超出视口时，用户 MUST 能通过滚动查看全部行，不得截断或隐藏数据。
- **FR-011**: 表格 MUST 使用页面原生的文本选择与复制能力（用户能选中单元格文字并复制）。
- **FR-012**: 系统 MUST NOT 要求用户登录，MUST NOT 提供用户、角色或权限相关界面。

### Key Entities *(include if feature involves data)*

- **项目（Project）**：一个可被独立查看的数据集合，是用户切换查看的单位。属性：标识、名称。
- **字段定义（Field Definition）**：描述一个项目里的一列。属性：所属项目、列名、类型、可选值（枚举类字段）、显示顺序、是否可见。
- **数据行（Row）**：某项目下的一条记录，由各列的值构成。
- **数据存储（Data Store）**：tableflow 自己持有的权威数据（项目、字段定义、数据行）。v0 以最小样例初始化，不迁移原平台存量数据。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 局域网环境、浏览器禁用缓存时，从打开页面到14行数据全部可见 ≤ 500ms（取5次测量的中位数）。
- **SC-002**: 在关闭硬件加速的浏览器中连续滚动5秒，平均帧率 ≥ 50fps，且不出现超过50ms的长任务。
- **SC-003**: 在数据层新增一列后，刷新页面即可看到该列；从改完数据到列可见 ≤ 1分钟，期间无代码发布。
- **SC-004**: 数据存储中的值更新后，用户重新打开页面即可看到新值，命中率 100%（不出现陈旧值）。
- **SC-005**: 在20个项目、单项目500行数据的规模下，项目切换与滚动均可正常使用，无崩溃、无数据缺失。
- **SC-006**: 用户从打开页面到确认某项目状态，操作不超过2步（选项目 → 看表）。

## Assumptions

- 使用者位于局域网内，v0 不做登录、不做字段级与行级权限（权限已列入宪法非目标）。
- 数据归属：tableflow 自有数据存储为权威数据；v0 不做存量数据迁移，也不与原平台保持同步，数据以最小样例初始化。
- 规模假设：项目数 ≤20，单项目行数 ≤500；验收样本为14行。
- 字段类型 v0 至少覆盖：文本、数字、日期时间、枚举（含状态类取值）；未识别类型回退纯文本。
- 目标浏览器为近两年版本的 Chrome / Edge（PC 桌面）。
- 日期时间按浏览器本地时区显示。
- 表格默认显示全部可见字段并按定义顺序排列；v0 不提供用户自定义列序、列宽保存（视图体系属宪法非目标）。
- 不要求"实时推送"：用户刷新或重新打开页面即视为获取最新状态。

## 未来范围（v1，不在本 spec 实现）

- **Agent 写接口**：本项目将在 v1 提供 Agent 使用的写接口，必须具备字段级契约、写入审计留痕、成功／失败／未知三态语义（宪法原则 I）。v0 MUST NOT 实现，也 MUST NOT 预留占位路由、开关或空实现（宪法原则 VII）。
