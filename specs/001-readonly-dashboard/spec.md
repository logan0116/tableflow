# Feature Specification: TableFlow 多维表格看板（v0）

**Feature Branch**: `001-readonly-dashboard`

**Created**: 2026-11-06

**Status**: Draft

**Input**: User description: "本质是多维表格项目：①一个项目下有多个表格；②表格字段用户可通过 Agent 定义；③一个项目下的表格可相互关联。人只读、Agent 读写。"

## Clarifications

### Session 2026-11-06

- Q: SC-001 的 500ms 应计到哪一帧？ → A: 第14行首次可见（首帧渲染完成），不含字体加载、图标与网络空闲。
- Q: 切换表格后、新数据返回前，表格区域显示什么？ → A: 立即清空上一表格的行并显示加载提示，直到新数据到达。
- Q: 数据行里"某列没有键"和"键存在但值为 null"怎么显示？ → A: 两者都显示空单元格，v0 不做区分。
- Q: 打开看板时默认选中哪个项目？ → A: 按 id 升序的第一个项目。
- Q: 快速连续切换时，先发出但后返回的响应怎么处理？ → A: 丢弃过期响应，只渲染当前选择。
- Q: Agent 写接口放在哪一版？ → A: v0 就提供（原 v1 计划提前），需带契约、审计、三态。
- Q: 关联要做到什么程度？ → A: 显示目标行标签，标签可点开查看该行明细（只读弹层）。
- Q: 现有 001 产物怎么处理？ → A: 直接改写 001，不另开 002。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 项目内浏览多张表格 (Priority: P1)

用户打开看板，选一个项目，看到该项目下的全部表格，选中其中一张后看到它的列与数据行。一个项目不再等于一张表。

**Why this priority**: 多维表格的第一层结构。若项目只能装一张表，后续的关联与字段定义都无处安放。

**Independent Test**: 造一个含两张表的项目，打开看板，在两张表之间切换，每次看到各自的列与行。

**Acceptance Scenarios**:

1. **Given** 项目 A 下有"任务""人员"两张表，**When** 用户选择项目 A，**Then** 页面列出这两张表并默认选中第一张。
2. **Given** 用户正在看"任务"表，**When** 切换到"人员"表，**Then** 页面显示"人员"表的列与行，不再显示"任务"表的任何行；切换瞬间清空旧行并显示加载提示。
3. **Given** 某张表没有数据行，**When** 用户选中它，**Then** 显示"暂无数据"的空表状态并保留列头。

---

### User Story 2 - Agent 定义表与字段并写入数据 (Priority: P2)

Agent 通过写接口创建表格、新增/修改/删除字段、写入数据行。人刷新看板就能看到变化，不需要改代码、不需要发版。

**Why this priority**: 字段是业务配置而不是代码。只有 Agent 能定义字段，多维表格才不是"改一列发一次版"。

**Independent Test**: 用写接口给项目新增一张表与一个字段，再写入一行数据，刷新页面可见新表、新列、新行。

**Acceptance Scenarios**:

1. **Given** 项目 A 已存在，**When** Agent 调用写接口创建表"设备"，**Then** 刷新后项目 A 下出现该表。
2. **Given** 表"设备"已存在，**When** Agent 新增字段"负责人"（text），**Then** 刷新后该列出现，位置由字段顺序决定。
3. **Given** 表"设备"有字段"负责人"，**When** Agent 写入一行数据，**Then** 刷新后该行出现且值正确。
4. **Given** 一次写入的字段校验失败，**When** 接口返回失败，**Then** 数据不落库，且该次失败仍留下审计记录。

---

### User Story 3 - 关联字段与明细查看 (Priority: P3)

某张表的一列可以指向同项目内另一张表的行。看板显示目标行的标签；点击标签可以查看该行的字段明细。

**Why this priority**: 关联是多维表格的核心能力，但它建立在"多表"与"字段可定义"之上。

**Independent Test**: 表 A 有一个 relation 字段指向表 B；打开表 A 看到目标行标签，点击后弹层显示表 B 该行的全部字段。

**Acceptance Scenarios**:

1. **Given** 表 A 的字段"负责人"关联到表 B，**When** 用户打开表 A，**Then** 该列显示目标行在表 B 中的标签。
2. **Given** 表 A 某行关联到表 B 的某行，**When** 用户点击该标签，**Then** 弹层显示表 B 该行的全部字段与值，且弹层不可编辑。
3. **Given** 关联的目标行已被删除，**When** 用户打开表 A，**Then** 该格显示"关联已失效"，页面不报错。
4. **Given** 表 A 关联表 B、表 B 又关联表 A，**When** 查看明细，**Then** 只展开一层，不递归展开。

---

### Edge Cases

- 项目下没有任何表格：显示"暂无表格"空状态，不报错。
- 表格没有任何数据行：显示"暂无数据"并保留列头。
- 单元格值为空：显示空单元格；键缺失与 `null` 一律按空单元格处理。
- 字段类型无法识别：按纯文本显示，页面不报错。
- 关联目标行不存在：显示"关联已失效"。
- 写接口字段校验失败：返回失败且不落库，同时留下失败审计记录。
- 快速连续切换表格：丢弃过期响应，只渲染当前选择。

## Requirements *(mandatory)*

### Functional Requirements

**读侧（人）**

- **FR-001**: 系统 MUST 列出全部项目，并允许用户选择一个项目。
- **FR-002**: 系统 MUST 列出所选项目下的全部表格，并允许用户选择一张表。
- **FR-003**: 系统 MUST 以表格形式呈现所选表的字段与数据行；列的顺序与可见性 MUST 由字段定义决定。
- **FR-004**: 关联字段 MUST 以目标行的 id 作为标签显示；MUST NOT 取目标表某个字段的值当标签。
- **FR-005**: 用户点击关联标签时，系统 MUST 以只读弹层显示目标行的全部字段与值；弹层 MUST NOT 提供任何编辑入口。
- **FR-006**: 每次打开或刷新页面 MUST 重新读取数据；页面 MUST NOT 展示上一次请求或上一次会话留下的数据。
- **FR-007**: 项目无表格、或表格无数据行时，系统 MUST 显示中文空状态，MUST NOT 显示错误。
- **FR-008**: 数据存储不可达或超时时，系统 MUST 显示中文错误提示与重试入口，MUST NOT 用旧数据填充。
- **FR-009**: 切换表格后、新数据返回前，系统 MUST 立即清空上一表格的数据行并显示加载提示。
- **FR-010**: 快速连续切换时，系统 MUST 丢弃过期响应，只渲染当前选择。
- **FR-011**: 表格 MUST 由 DOM 渲染，单元格文本 MUST 可选中复制。
- **FR-012**: 界面文案 MUST 全部为中文。
- **FR-013**: 人侧接口 MUST 只有 GET；前端 MUST NOT 提供任何写入、编辑、删除入口。

**写侧（Agent）**

- **FR-014**: Agent 写接口 MUST 支持创建、重命名、删除表格（删除时级联删除其字段与行）。
- **FR-015**: Agent 写接口 MUST 支持新增、修改、删除字段；字段定义 MUST 包含 id、所属表、名称、类型、选项、顺序、可见性；relation 类型 MUST 指定目标表。
- **FR-016**: Agent 写接口 MUST 支持新增、更新、删除数据行；relation 字段的值 MUST 为目标行 id 的数组（单值也写成单元素数组）。
- **FR-017**: 每次写入（成功或失败）MUST 产生一条审计记录，包含操作者标识、时间、动作、目标、结果。
- **FR-018**: 写入 MUST 返回三态语义：成功、失败、未知；校验失败 MUST 返回失败且不落库；未知 MUST NOT 当作成功。
- **FR-019**: 写接口 MUST 要求请求方提供 Agent 标识（请求头），该标识 MUST 写入审计记录。

### Key Entities

- **项目（Project）**：一组表格的容器，是用户切换查看的第一层单位。
- **表格（Table）**：项目内的一张多维表格，持有字段定义与数据行。
- **字段（Field）**：表格的一列。属性：标识、所属表、名称、类型（text / number / datetime / enum / relation）、选项、顺序、可见性；relation 类型额外记录目标表。
- **数据行（Row）**：某张表下的一条记录，由各字段的值构成。
- **关联（Relation）**：字段值指向目标表的行；展示为目标行标签，可点开查看明细。
- **审计记录（Audit）**：一次写入的留痕，包含操作者、时间、动作、目标与结果。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 局域网、浏览器禁用缓存时，从打开页面到14行首次可见 ≤ 500ms（5次中位数）；计时终点为第14行首帧绘制到屏幕。
- **SC-002**: 关闭硬件加速的浏览器中连续滚动5秒，平均帧率 ≥ 50fps，且无超过50ms的长任务。
- **SC-003**: Agent 新增一列后，刷新页面即可看到；从接口返回到列可见 ≤ 1分钟，期间无代码发布。
- **SC-004**: 点击关联标签到弹层显示明细 ≤ 300ms（局域网、本机数据）。
- **SC-005**: 每次写接口调用都能在审计表中查到对应记录，覆盖率 100%。
- **SC-006**: 在20个项目、每项目10张表、单表500行的规模下，切换与滚动均可用，无崩溃。
- **SC-007**: 用户从打开页面到确认某张表的状态，操作不超过2步（选项目 → 选表）。

## Assumptions

- 关联标签统一用目标行 id（用户 2026-11-06 决定），不取目标表字段值。
- relation 值一律为数组；单元格中以顿号分隔显示，弹层逐条列出明细。
- 删除表格、字段、行均为硬删除（v0 不做软删除与回收站），依赖审计留痕与 Agent 重建能力。
- Agent 身份通过请求头 `X-Agent-Id` 传入；v0 不做鉴权，只做留痕。
- 规模假设：项目 ≤20，每项目表格 ≤10，单表行数 ≤500；验收样本为14行。
- 字段类型 v0 覆盖 text / number / datetime / enum / relation；未识别类型回退纯文本。
- 目标浏览器为近两年版本的 Chrome / Edge（PC 桌面）。
- 日期时间按浏览器本地时区显示。
