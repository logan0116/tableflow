# Feature Specification: 四组等宽与灯提示

**Feature Branch**: `031-col-light`

**Created**: 2026-11-22

**Status**: Draft

**Input**: 需求 031-AR。①026 合并出的独立需求/依赖需求/测试/Bug 四列按内容估算宽度，长短不一（`0/0` 很窄、`150/150` 较宽），横向看过去参差；改成四列等宽，放弃 min 策略。②灯组只有颜色，悬停才靠浏览器原生 title 提示，需要确认名称与状态可见。

## 背景与问题证据

| 问题 | 证据 | 影响 |
|---|---|---|
| 四组合并列宽不等 | 028 按内容估算，`0/0` 与 `150/150` 宽度不同 | 版本表横向参差，扫读不齐 |
| 灯提示不够明确 | 灯只有颜色与原生 `title` | 悬停时浏览器提示延迟、样式不可控 |
| 比率数字偏小、点击目标像链接 | 合并列复用 relation 的下划线链接样式，12.5px 文字、可点区域只有文字本身 | `150/150` 难读，点开弹窗要精确点字 |

## Clarifications

### Session 2026-11-22

- Q: 等宽取多少？ → A: 四列统一宽度，能装下 `999/999` 这类文本即可（约 96–112px），具体值由实现定并在规格里写明。
- Q: 放弃 min 策略的范围？ → A: 只针对这四组合并列；其余列仍按内容估算。
- Q: 灯提示用什么形式？ → A: 悬停显示自定义提示（节点名 + 四态文案），不用浏览器原生 title 的默认延迟样式。
- Q: 比率数字与点击目标怎么改？ → A: 数字字号加大到不小于 14px（正文是 12.5px）；整格做成按钮态，可点区域覆盖单元格，不再只是文字下划线可点。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 四组合并列等宽 (Priority: P1)

独立需求、依赖需求、测试、Bug 四列宽度一致，横向对齐。

**Independent Test**: 版本表里四列表头与单元格宽度相同。

**Acceptance Scenarios**:

1. **Given** 版本表渲染完成，**When** 量四列的宽度，**Then** 四列相等。
2. **Given** 某行四组值分别为 `0/0`、`0/0`、`150/150`、`0/0`，**When** 看该行，**Then** 四列仍等宽，长文本不撑宽列。
3. **Given** 版本号很长或很短，**When** 看其余列，**Then** 其余列不受四组等宽影响。

### User Story 2 - 灯悬停显示名称与状态 (Priority: P1)

鼠标悬停某个灯，立即看到该节点名称与当前状态文案。

**Independent Test**: 悬停第三个灯，提示显示「开发：未开始」。

**Acceptance Scenarios**:

1. **Given** 六个灯，**When** 悬停任一个，**Then** 显示「节点名：状态」的提示。
2. **Given** 节点状态为 done，**When** 悬停，**Then** 提示显示「已完成」。
3. **Given** 节点状态为 failed，**When** 悬停，**Then** 提示显示「失败」。
4. **Given** 移开鼠标，**When** 提示消失，**Then** 不残留遮挡。

### User Story 3 - 比率数字可读、整格可点 (Priority: P1)

`999/999` 这类数字要看得清，点开清单不用精确点字。

**Why this priority**: 合并列现在是细链接，数字小、可点区域窄，实际用起来费劲。

**Independent Test**: 看某行 `150/150`，数字明显大于正文；点该列空白处也能打开弹窗。

**Acceptance Scenarios**:

1. **Given** 某行四组合并列显示 `150/150`，**When** 看字号，**Then** 不小于 14px（大于正文 12.5px）。
2. **Given** 鼠标移到该列任意位置，**When** 看反馈，**Then** 整格呈现按钮态（背景或描边变化），不是只有文字下划线。
3. **Given** 点击该列的空白处或数字，**When** 点击，**Then** 都能打开关联清单，不要求精确命中文字。
4. **Given** 该列等宽，**When** 看四组数字，**Then** 数字对齐一致（右对齐或居中统一）。

## Requirements *(mandatory)*

- **FR-001**: 独立需求、依赖需求、测试、Bug 四组合并列 MUST 等宽。
- **FR-002**: 等宽 MUST 不受单元格内容长度影响。
- **FR-003**: 四组之外的列 MUST 保持原有列宽策略（028 的 min 策略）。
- **FR-004**: 灯 MUST 提供悬停提示，内容为节点名与四态文案。
- **FR-005**: 灯提示 MUST 不依赖浏览器原生 title 的默认样式与延迟。
- **FR-006**: 四组合并列的比率数字字号 MUST 不小于 14px。
- **FR-007**: 四组合并列 MUST 整格可点（按钮态），MUST NOT 只有文字可点。
- **FR-008**: 四组数字 MUST 对齐一致。

## Non-Goals

- 不改列宽的整体策略（其余列仍按 028）。
- 不改灯的配色与数量。
- 不改合并列的数据来源。

## Success Criteria

- 四列宽度完全相等。
- 悬停任一灯可见「节点名：状态」。
- 其余列宽度不变，`npm run build` 通过。
