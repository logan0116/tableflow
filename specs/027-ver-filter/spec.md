# Feature Specification: 版本表筛选

**Feature Branch**: `027-ver-filter`

**Created**: 2026-11-22

**Status**: Draft

**Input**: 需求 027-AR。版本表积累到 13 个版本行后，日常只关心当前在研或刚发布的那一个，却要在整张表里找；需要默认聚焦最新版本，并能切到指定版本查看。

## 背景与问题证据

| 问题 | 证据 | 影响 |
|---|---|---|
| 版本行多、当前版本难找 | 线上 `tf-ver` 有 13 行（v0.1.0…v0.7.1） | 打开就先扫一遍找最新版本 |
| 没有版本维度筛选 | 工具栏只有跨列关键字筛选 | 想只看某一版要手工找行 |

## Clarifications

### Session 2026-11-22

- Q: 「只展示最新版本关联」指哪张表？ → A: 指版本表本身——默认只显示最新版本（版本号语义序最大）那一行；切到「全部」或其他版本时再展开。若实际想要的是"需求/用例表按版本过滤"，属另一条需求。
- Q: 筛选会改数据吗？ → A: 不会。纯前端展示过滤，不改接口、不改任何行。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 默认聚焦最新版本 (Priority: P1)

打开版本表时只看到最新版本那一行，不需要在一堆历史版本里找。

**Why this priority**: 日常最常看的就是当前在研版本。

**Independent Test**: 刷新页面，版本表只显示 v0.7.1 一行，且筛选器显示「最新版本」。

**Acceptance Scenarios**:

1. **Given** 版本表有多个版本行，**When** 首次打开，**Then** 只显示版本号语义序最大的那一行。
2. **Given** 只显示最新版本，**When** 看筛选器，**Then** 当前选中项是「最新版本」。
3. **Given** 最新版本是 `v0.7.1`，**When** 新增 `v0.7.2` 后刷新，**Then** 默认显示切到 `v0.7.2`。

### User Story 2 - 按版本筛选 (Priority: P1)

可以从筛选器切到某个历史版本或「全部」，只显示对应的行。

**Why this priority**: 回溯与对比时需要看历史版本。

**Independent Test**: 在筛选器选 v0.7.0，表格只剩该行；选「全部」恢复 13 行。

**Acceptance Scenarios**:

1. **Given** 筛选器，**When** 选择某个历史版本，**Then** 表格只显示该版本行。
2. **Given** 筛选器，**When** 选择「全部」，**Then** 显示全部版本行，条数等于接口返回总数。
3. **Given** 已选某版本，**When** 刷新页面，**Then** 选择被记住（与现有 UI 偏好一致）。
4. **Given** 已选某版本，**When** 该版本被删除，**Then** 回退到「最新版本」而不是空白。

### User Story 3 - 筛选不改数据与判定 (Priority: P1)

筛选只影响展示，接口、计算字段与发布条件不受影响。

**Why this priority**: 这是展示层改动，不能碰判定。

**Independent Test**: 筛选前后读同一版本的发布条件，值一致。

**Acceptance Scenarios**:

1. **Given** 筛选到某版本，**When** 对比接口返回的该行与界面显示，**Then** 字段值一致。
2. **Given** 筛选状态，**When** 跑 `check_board --base`，**Then** 差异仍为 0。

### User Story 4 - 语义序与异常输入 (Priority: P2)

版本筛选在版本号跨位数、本地状态损坏、与角色叠加时都表现正确。

**Acceptance Scenarios**:

1. **Given** 版本表同时有 `v0.9.0` 与 `v0.10.0`，**When** 选「最新版本」，**Then** 显示 `v0.10.0`（按数字比较，不是字符串）。
2. **Given** localStorage 里存着已被删除的版本号，**When** 打开页面，**Then** 回退到「最新版本」而不是空白。
3. **Given** localStorage 内容损坏，**When** 打开页面，**Then** 不抛错，按「最新版本」渲染。
4. **Given** 已选某版本并切到「软件测试」角色，**When** 再看版本表，**Then** 版本筛选仍生效。

## Requirements *(mandatory)*

- **FR-001**: 版本表 MUST 默认只展示版本号语义序最大的行，MUST 提供「最新版本/全部/具体版本」三种筛选。
- **FR-002**: 版本语义序 MUST 按 `v<主>.<次>.<修>` 数字比较，MUST NOT 用字符串排序（`v0.10.0` 要大于 `v0.9.0`）。
- **FR-003**: 筛选选择 MUST 记住（localStorage），非法或已删除的版本 MUST 回退到「最新版本」。
- **FR-004**: 筛选 MUST 只影响前端渲染，MUST NOT 改变接口调用、计算字段或发布条件。
- **FR-005**: 其他表（需求/用例/缺陷）MUST NOT 受本需求影响。

## Non-Goals

- 不做需求/用例表按版本过滤（另立需求）。
- 不改接口与数据。
- 不改列合并与灯组（026 的范围）。

## Success Criteria

- 首次打开版本表只显示最新版本一行。
- 切到「全部」显示全部 13 行，切回某版本只显示 1 行。
- 刷新后筛选保持；删除所选版本后回退到最新版本。
